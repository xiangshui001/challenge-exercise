# 00｜范围、材料依据与状态

## 1. 原材料直接支持什么

来源为用户上传的《跨模态检索实验设计与实现——从理论算法到工程落地的完整实践路径》，戴波，封面标注 2026 年 4 月，共 22 页。本仓库保留页码定位，不公开转载原 PDF。

| 材料位置 | 原材料内容概括 | 本方案如何对应 |
|---|---|---|
| 第 14 页，实验五 | 设计、计算评估指标，形成量化评估体系 | 双向 Recall@1/5/10、NDCG@10，固定协议 |
| 第 14 页，实验五 | 通过错误案例分析定位问题、指导优化 | 修复/退化统计，主体、属性、动作、关系等错误审查 |
| 第 14 页，实验五 | 数据增强、模型架构升级等优化策略 | 预训练模型升级为基础优化；重排为可选优化 |
| 第 14 页，实验五 | Top-10 召回率稳定达到 85% 以上 | 定义主方向及候选库，运行后如实报告是否达到 |
| 第 21 页，汇总表 | 提及 Recall@K / NDCG@K、错误分析与优化 | 将两类指标纳入统一结果表 |
| 第 17 页，拓展 | 使用预训练多模态模型降低从零开发成本 | 复用预训练权重，不在本项目重新预训练 |

原材料没有为实验五规定 Flickr30K、具体模型、候选库大小、检索方向、置信区间或选择性重排。这些均是本方案为了可执行性补充的设计，不冒充课程原要求。材料中的“语义匹配准确率”与“Recall@10”也不自动等同于二分类 accuracy，具体计算在协议中明确。

## 2. 用户给出的实施约束

只需独立完成实验五，不做实验一、二、三、四、六；不讨论其他实验对课程成绩的影响。用户 2026-10-11 提供四张约 80GB A100、驱动 570.211.01 的快照，各卡当时仅占用 10MiB。GPU 0/1 与 2/3 分属两个 NUMA 节点，拓扑未显示 NVLink；优先用独立单卡进程，不增加分布式训练。服务器独立环境 torch 2.8.0+cu126、transformers 4.57.3 已通过依赖检查和四卡 BF16 小矩阵检查。可用机时、API 模型和预算未确定，继续先做真实模型小试再定批量与预算；空闲快照不代表持续独占资源。

2026-10-19 数据审计记录中的最新快照：GPU 0/3 分别占用 59770/30625MiB，GPU 1/2 各约 10MiB。下一步先检查实时占用，再安排 B0/CLIP 使用 GPU 1、B1/SigLIP 2 使用 GPU 2；不清理现有进程。

## 3. 两个交付层次

**基础版**：现成数据与预训练模型、CLIP→SigLIP 2 比较、正式指标、错误分析、至少一次优化尝试、冻结配置与复测。排序融合可以作为廉价对照，不要求它一定胜过单模型。

**研究版**：在相同 SigLIP 2 初检结果上比较全查询重排、选择性重排、同预算随机重排，增加小规模改写鲁棒性诊断。研究版不是基础版的前置条件；时间不足时停止在基础版，不扩大成系统开发。

## 5. 名词约定

T2I：文本检索图像。I2T：图像检索文本。初检：在完整候选库中按双编码器相似度排序。重排：只重新排列初检的前 M 个候选。基础模型无需本地任务训练，不代表可以证明其上游训练数据绝不包含评测图片；报告采用“无本地任务训练评估”，避免未经验证的训练数据无污染声明。

评估稳定性分为环境复现和样本统计不确定性。95% 置信区间是本项目建议增加的证据，不是原材料明文规定的额外门槛。
