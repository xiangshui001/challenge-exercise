# M0｜Astra 当前任务清单（按顺序执行）

**当前唯一主目标**：先证实或证伪“现有视觉语言模型在义项、语义关系与视觉证据边界上存在可重复的问题”，再决定是否训练新模型。协议见 [17_M0_PROBLEM_VALIDATION.md](17_M0_PROBLEM_VALIDATION.md)。

## P0：接管资产、核验数据和协议

- 检查 main、PR #3/#5 与现有服务器 SigLIP-base 结果；复用代码，不覆盖旧分支、服务器缓存和实验记录。
- 核实 SugarCrepe++、SNLI-VE/校正版、Visual-WSD 官方下载、许可、样本结构和评分方式；Winoground 可选。
- 用固定种子按类别分层抽样，目标 120+120+40+20 组。先做20组小试，固定 ID/划分/图片指纹，输出 data audit 与标注规范。
- **验收**：数据来历清楚；官方标签与人工判定分开；无分组泄漏；不将全部基准指标硬混合。

## P1：建立现成模型的原始表现

- 用已验证SigLIP-base先跑适用的匹配/排序诊断；再选至少一个独立强基线，必要时加Qwen-VL三类判断，先限量控制成本。
- 每个基准单独计算正确指标；逐样本记录原始得分、输出、样本ID和错误类型，人工核验重点疑难项。
- **验收**：至少一个真实基线可复算，最好有第二模型；记录错误、有效分母和置信区间；不能把相似度冒充三类概率。

## P2：最小辞书语义干预（不训练）

- 在固定探索子集比较 K0 原始输入 / K1 等知识量普通释义 / K2 带方向与类型的义项关系。
- 加入关系打乱、去掉图像或替换图像的控制；设置人工Oracle作为单独上限。
- **验收**：同数据、同模型、可核对的知识来源，解释增益/退化，确认集不得重复调参。

## P3：形成判断并收尾

- 写 docs/M0_REPORT.md：哪些失败反复出现，哪些只是噪声、提示敏感或标注问题；辞书关系是否超过普通释义；哪些错误需要视觉局部证据。
- 如果证据支持，提出下一阶段**一个**最值得训练的模块；如果无支持，明确建议停止或转向。
- 提交可复现脚本、清洗后的结果摘要、数据/模型版本与PR；不提交未经许可的图片、API密钥、大模型权重。
